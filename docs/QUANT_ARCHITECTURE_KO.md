# 퀀트 구조 설계안 (2026-11-15)

퀀트 회사가 쓰는 표준 구조를 이 프로젝트에 맞게 옮기는 계획이다.

**진행 상황 (2026-11-15):** 1 ~ 4단계를 했다.
- 연구 도구: `research/alpha.py`(신호, IC, 기대수익 모델), `research/risk.py`(변동성, 베타), `research/portfolio.py`(비용을 넣은 최적화와 장부). 테스트는 `tests/test_quant.py`.
- 신호 탐색: `docs/research/quant_explore.md`. 오래 가는 신호는 자금조달비, 낮은 변동성, 낮은 베타 셋이었다.
- 등록: `docs/research/direction_preregistration_v15.md`.
- 그림자 장부: `predictor/shadow.py`, 대시보드 "그림자 장부" 칸. 판정은 2027-05-15.

**먼저 밝혀 둘 것.** 구조는 없는 예측력을 만들지 못한다. 구조가 하는 일은 두 가지다.
- 있는 예측력을 비용과 위험에 낭비하지 않는 것.
- 예측력이 정말 있는지를 정직하게 재는 것.

v6 ~ v14에서 잰 예측력은 작다. 7일 동안 가장 좋게 본 10%와 가장 나쁘게 본 10%의 실제 차이가 0.81%p이고, 롱과 숏을 한 번씩 사고파는 비용이 0.40%다. 이 설계가 성공해도 큰 수익을 약속하지 않는다.

## 2. 표준 구조: 다섯 층과 검증

```
데이터 ─▶ 알파(신호) ─▶ 위험 ─▶ 포트폴리오 구성 ─▶ 실행
   │          │           │            │             │
   └──────────┴───────────┴────────────┴─────────────┴──▶ 검증·감시 (신호별 성적, 그림자 장부, 중단 규칙)
```

각 층은 한 가지 일만 하고, 다음 층에 숫자 하나를 넘긴다.

| 층 | 하는 일 | 다음 층에 넘기는 것 |
|---|---|---|
| 데이터 | 그 시점에 알 수 있던 값만 정리 | 코인 × 시각 표 |
| 알파 | 각 코인이 앞으로 중간보다 얼마나 더 오를지 | 기대 상대수익 α (%, 기간당) |
| 위험 | 각 코인이 얼마나 흔들리고 시장과 얼마나 같이 움직이는지 | 변동성 σ, BTC 베타 β |
| 포트폴리오 | α, σ, β, 비용으로 목표 비중을 정함 | 코인별 목표 금액 |
| 실행 | 목표와 지금의 차이를 주문으로 바꿈 | 체결과 실제 비용 |

## 3. 층별 설계

### 3-1. 데이터 층

이미 있는 것:
- 60개 코인의 4시간봉과 자금조달비(2020-09 ~).
- 실시간으로만 모이는 것: 미결제약정, 롱숏 비율, 호가 쏠림과 스프레드, 강제청산(`predictor/collect.py`).

빠진 것:
- **그 시점의 코인 목록.** v14는 "지금" 큰 코인 30개로 과거를 돌려서 생존 편향이 있었다. 매달 1일에 "그때까지 1년 거래대금 상위 N개"를 다시 골라야 한다.
- **상장 폐지된 코인.** 바이낸스 공개 보관소(data.binance.vision)에 폐지된 선물의 과거 봉이 있다. 넣으면 생존 편향이 줄어든다.

### 3-2. 알파 층: 신호 여러 개를 따로 재고 합친다

신호마다 같은 방식으로 성적을 잰다.
- **IC(정보 계수)**: 각 시각에 신호 순위와 실제 상대수익 순위의 상관. 퀀트에서 신호를 평가하는 기본 숫자다. 0.02 ~ 0.05면 쓸 만한 신호로 본다.
- **IC가 해마다 같은 부호인가.** 한 해에 몰리면 버린다.
- **IC가 기간에 따라 어떻게 줄어드나**(4시간, 1일, 3일, 7일). 빨리 사라지는 신호는 비용을 못 넘는다(v12의 교훈).
- **신호의 회전율**: 다음 시각 신호와의 순위 상관. 낮을수록 거래가 잦다.

후보 신호. 경제적인 이유가 있는 것만 넣는다.

| 신호 | 이유 | 데이터 |
|---|---|---|
| 중기 모멘텀 (2 ~ 4주 수익률) | 코인 시장에서 가장 많이 보고된 요인 | 있음 |
| 단기 반전 (4시간 ~ 1일) | 과잉 반응의 되돌림. 회전율이 높아 비용 주의 | 있음 |
| 캐리 (자금조달비) | 숏이 자금조달비를 받는 쪽. v12에서 숏 쪽이 이 비용에 졌다 | 있음 |
| 저변동성 | 변동성이 큰 코인이 위험 대비 덜 번다는 요인 | 있음 |
| 거래대금 변화 | 관심 쏠림 | 있음 |
| 미결제약정 변화, 롱숏 쏠림 | 포지션 과밀의 되돌림 | 실시간만 (30일 이전 없음) |
| 지금의 크기 모델 (v14) | 위 특징의 조합 하나 | 있음 |

신호를 합치는 법:
- 각 신호를 시각마다 코인 간 z점수로 바꾼다.
- **기대 상대수익 α = IC × σ × z** (그리놀드의 공식). 순위만 있던 신호가 "몇 %"가 되어 비용과 직접 견줄 수 있다.
- 여러 신호의 α는 지난 IC를 0 쪽으로 줄인 값을 가중치로 더한다. 신호끼리 겹치면(상관이 높으면) 가중치를 나눠 갖게 한다.

### 3-3. 위험 층

넣을 것(새 라이브러리 없이 numpy로 충분):
- **코인별 변동성 σ**: 지수 가중 표준편차(반감기 약 2주).
- **BTC 베타 β**: 지난 60일 회귀.
- **단일 요인 위험 모델**: 공분산 = β β' × 시장 분산 + 코인 고유 분산(대각).

쓰는 곳:
- 변동성이 큰 코인은 금액을 줄인다.
- 포트폴리오의 베타를 0 근처로 맞춘다.
- 포트폴리오 전체의 예상 변동성을 목표(예: 연 20%)에 맞춘다. 낙폭 40% 이상이 나왔던 문제를 여기서 막는다.

### 3-4. 포트폴리오 층: 지금까지 가장 크게 빠져 있던 부분

코인마다 아래를 최대로 하는 비중 w를 고른다.

```
α·w  −  λ·σ²·w²  −  c·|w − w_지금|
기대수익   위험 벌점     거래 비용 (c = 그 코인의 한쪽 비용)
```

이 식은 풀이가 닫힌 형태로 나온다.
- `α − 2λσ²·w_지금`이 비용 c보다 크면: w = (α − c) / (2λσ²)
- `−c`보다 작으면: w = (α + c) / (2λσ²)
- 그 사이면: **거래하지 않는다** (w = w_지금)

즉 "비용보다 기대수익 변화가 작으면 그대로 둔다"는 구간이 비용에서 저절로 나온다. v13의 "상위 50% 안이면 유지"처럼 결과를 보고 고르는 숫자가 아니다.

제약:
- 베타 합이 0 근처(α에서 베타 성분을 빼는 것으로 맞춘다).
- 코인 하나는 자금의 10% 이하, 전체 총액은 자금의 1배 이하.
- **최소 주문 금액.** 자금 50 USDT로는 BTC, ETH처럼 최소 주문이 큰 코인을 잡을 수 없다. 30개 코인에 나눠 거는 구조는 지금 자금으로는 실제로 실행할 수 없다. 그래서 첫 단계는 주문 없는 그림자 장부다.

### 3-5. 실행 층

이미 있는 것: 진입 전 호가로 슬리피지를 재고 한도를 넘으면 거부하는 기능(2026-11-15부터 가상 봇에 적용).

넣을 것:
- **코인별 비용 추정**: 수집 중인 호가 스프레드와, 봇이 기록하는 실제 슬리피지로 코인마다 c를 정한다. 지금은 모든 코인이 0.10%로 같다.
- 지정가는 v7, v13에서 시장가보다 나빴으므로 쓰지 않는다.

### 3-6. 검증과 감시

- **신호는 따로 검증한다.** 전략 전체의 수익 곡선 대신 신호마다 IC를 잰다. 수익 곡선 하나는 우연이 크고(v14에서 무작위 숫자로도 -86 ~ +26%), IC는 표본이 훨씬 많다.
- **시험 횟수를 센다.** v1 ~ v14에서 수십 가지를 시험했다. 가장 좋은 결과의 샤프 비율은 시험 횟수만큼 깎아서 본다(deflated Sharpe).
- **그림자 장부.** 예측기가 4시간마다 위 구조로 목표 포트폴리오를 계산하고, 주문 없이 비용을 빼고 장부에 기록한다. 과거는 모두 본 데이터라 **앞으로 쌓이는 이 기록이 유일하게 깨끗한 증거**다.
- **중단 규칙.** 신호의 최근 8주 IC가 0 아래로 내려가면 그 신호의 가중치를 0으로 한다. 그림자 장부 낙폭이 정한 값을 넘으면 멈추고 다시 본다.
- 아껴 둔 최종 확인 구간(2026-08-06 ~ 11-06)은 사용자 승인 뒤 한 번만 쓴다.

## 4. 이 프로젝트에 넣는 순서

| 단계 | 할 일 | 바뀌는 곳 | 실제 매매 영향 |
|---|---|---|---|
| 1. 연구 도구 | 신호 라이브러리와 IC 보고서, 위험 모델, 비용 넣은 최적화, 이 셋을 쓰는 시뮬레이터. 테스트 포함 | `research/alpha.py`, `research/risk.py`, `research/portfolio.py` | 없음 |
| 2. 신호 탐색 | 기준 코인 59개(이미 본 데이터)에서 신호별 IC 표. 증거가 아니라 후보 고르기 | 문서 | 없음 |
| 3. 등록 | 신호 목록, 합치는 법, λ, 비용, 판정 기준을 결과 보기 전에 v15로 등록 | `docs/research/` | 없음 |
| 4. 그림자 장부 | 예측기가 목표 포트폴리오와 가상 손익을 기록, 대시보드에 표시. 최소 3개월 | `predictor/`, `dashboard/` | 없음 (주문 없음) |
| 5. 최종 확인 (선택) | 사용자 승인 시 아껴 둔 석 달에 한 번 | 문서 | 없음 |
| 6. 연결 (통과 시에만) | 따로 만든 가상 계좌로 봇에 연결. 실거래 여부는 사용자가 정함 | 봇 | 가상 매매만 |

1 ~ 2단계는 며칠이면 된다. 4단계는 시간이 필요하다. 석 달 기록도 짧아서, 결과가 좋든 나쁘든 우연일 수 있다.

## 5. 다른 길: 추세 추종 (CTA 방식)

교차 단면(코인끼리 비교) 대신, 큰 코인 몇 개의 가격 추세를 따라가는 방식도 퀀트에서 오래 쓰였다.
- 예: BTC, ETH 각각 1 ~ 3개월 추세가 위면 롱, 아래면 숏, 변동성으로 금액을 맞춘다.
- 장점: 거래가 드물어 비용에 강하다. 코인 2 ~ 3개라 50 USDT로도 실행할 수 있다.
- 단점: 추세가 없는 시기에 오래 잃는다. 이 프로젝트의 과거 데이터에서 시험한 적이 없다.
- 지금 봇의 15분봉 규칙도 추세 계열이지만, 기간이 짧고 변동성 맞추기가 없다.

## 6. 하지 않을 것

- 시장 국면별 가중치 (v10에서 세 가지 방법 모두 실패).
- 적중률을 더 올리는 데만 집중하는 것 (적중률과 수익이 따로 논다는 것을 탐색 4에서 확인).
- 2023년 이후 상장 코인 (사용자가 원하지 않음).
- 결과를 본 뒤 규칙을 바꾸고 같은 데이터로 다시 판정하는 것.
