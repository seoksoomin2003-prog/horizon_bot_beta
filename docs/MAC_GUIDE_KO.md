# 맥북 실행 안내

서버나 systemd 없이 맥북에서 실행합니다. 기본은 **가상 매매**입니다. 실제 주문이 나가지 않고, API 키도 읽지 않으며, 거래소 공개 시세만 씁니다.

## 설치 (처음 한 번)

```bash
cd ~/Projects/horizon_bot_beta && ./run_mac.sh setup
```

## 가상 매매

시작:

```bash
./run_mac.sh start
```

현황:

```bash
./run_mac.sh status
```

최근 로그:

```bash
./run_mac.sh logs
```

중지:

```bash
./run_mac.sh stop
```

- 비정상 종료 시 자동으로 다시 시작합니다. 맥북을 재부팅하면 `start`를 다시 실행해야 합니다.
- 전원을 연결해 두세요. 덮개를 닫으면 잠자기로 기록이 끊길 수 있습니다. 다시 켜지면 놓친 1분봉으로 손절·익절을 다시 계산합니다.
- 시작 자금은 50 USDT입니다(실제 자산 규모에 맞춤, 2026-11-08). 바꾸려면 시작 전에 `.env`에 `PAPER_INITIAL_EQUITY=값`을 넣으세요.
- 기록은 `runtime/paper_binance/`, `logs/paper/`에 저장되고 실거래 폴더와 섞이지 않습니다. 초기화하려면 봇을 중지한 뒤 이 두 폴더를 지우면 됩니다.

## 가상 매매 결과의 한계

체결은 가정으로 계산합니다: 수수료 0.05%, 슬리피지 0.05%, 손절은 표시가격이 아닌 1분봉 체결가 기준입니다. 자금조달비용, 강제청산, 호가 깊이, 부분 체결은 반영하지 않으므로 실제 결과는 더 나쁠 수 있습니다. 거래가 적으면 수익성을 판단할 수 없습니다.

### 슬리피지 한도

- 진입 주문을 보내기 전에, 그 주문 수량으로 호가를 직접 계산해 예상 슬리피지를 구합니다. 한도(기본 0.5%)를 넘으면 주문을 보내지 않습니다.
- 호가를 읽지 못했거나 보이는 호가가 주문 수량보다 얇을 때도 보내지 않습니다.
- 체결되면 판단 시점 가격에서 실제로 얼마나 밀려 체결됐는지 기록합니다. 화면의 "최근 활동"에 "체결 슬리피지"로 나옵니다.

### 빗썸 ↔ 바이낸스 입출금 비용

화면의 평가 자산 아래에 왕복 비용과 본전이 되는 평가 자산이 나옵니다. 2026-11-12에 두 거래소의 수수료 표에서 확인한 값으로 계산합니다.

| 단계 | 비용 |
|---|---|
| 빗썸에서 리플(XRP) 매수 | 0.25% |
| 빗썸 → 바이낸스 전송 | 0.4 XRP |
| 바이낸스에서 리플을 테더로 환전, 돌아올 때 다시 리플로 환전 | 0.1%씩 |
| 바이낸스 → 빗썸 전송 | 0.2 XRP |
| 빗썸에서 리플 매도 | 0.25% |

- 시작 자금 50 USDT, 1 XRP = 1.05 USDT일 때 왕복 약 0.98 USDT입니다. 평가 자산이 약 50.98 USDT(+2.0%)를 넘어야 본전입니다.
- 이 비용은 거래마다가 아니라 자금을 넣고 뺄 때 한 번씩 듭니다. 그래서 거래 1건의 슬리피지에 넣지 않고 계좌 전체의 본전 기준으로 보여 줍니다.
- 두 거래소의 가격 차이(김치 프리미엄)와 전송 중 리플 가격 변동은 수수료가 아니라서 넣지 않았습니다. 실제 결과는 이보다 좋을 수도 나쁠 수도 있습니다.
- 수수료가 바뀌면 `paper/funding.py`의 값을 고치세요. 빗썸 최저 수수료(0.04%)를 신청하면 `BITHUMB_FEE`를 0.0004로 바꿉니다.

## 실거래 전 점검

실거래는 직접 판단해서 켜야 합니다. 원금 이상의 손실이 날 수 있는 선물 거래입니다. 켜기 전에 아래를 모두 확인하세요.

1. 가상 매매로 2~4주 이상 돌려 오류와 거래 내용을 확인했습니다.
2. API 키의 출금 권한이 꺼져 있습니다. 키가 서버 IP로 제한되어 있으면 새로 설정했습니다.
3. `.env`를 iCloud 동기화 밖에 두었습니다. Desktop이 iCloud 대상이면 폴더를 `~/Projects`로 옮기세요.
4. 거래소에서 실제 포지션과 미체결 주문을 직접 확인했습니다.
5. `runtime/binance/`에 예전 테스트가 남긴 값이 있습니다. 4번을 확인한 뒤 이 폴더를 백업하고 비웠습니다. 특히 `degradation_state.json`의 `CRITICAL_PROTECTION_FAILURE`가 남아 있으면 신규 진입이 막힙니다.
6. 거래소 계정의 레버리지와 마진 모드를 확인했습니다. 봇이 직접 설정하지 않습니다.
7. 맥북이 꺼지면 거래소의 손절 주문만 남습니다. 익절 분할, 손절가 이동, 재시도는 멈춥니다.

실거래 시작 (`.env`에 키가 있어야 하고, `DEMO_MODE`는 꺼야 하며, 확인 문구를 직접 입력해야 합니다):

```bash
./run_mac.sh start --live
```

## 보기 전용 화면

```bash
./run_dashboard.sh
```

브라우저에서 `http://127.0.0.1:8791`이 열립니다. 잔고, 포지션, 손익, 체결, 오류를 10초마다 새로 보여 줍니다. 끌 때는 `./run_dashboard.sh stop`을 실행합니다.

- 봇과 별개 프로그램이라 켜고 꺼도 봇에는 영향이 없습니다.
- 이 맥북에서만 열립니다. 가상 매매와 예측 기록기를 켜고 끌 수 있지만, 실거래는 켤 수 없습니다.
- `.env`를 읽지 않고 인터넷에 연결하지 않습니다. 그래서 미실현 손익은 보여 주지 않습니다.
- 맥북을 재부팅하면 다시 실행해야 합니다.

## 방향 예측 기록 (주문 없음)

```bash
./run_predictor.sh start
```

화면의 "예측 기록 켜기" 버튼으로도 켤 수 있습니다.

- 4시간봉이 마감될 때마다(한국 시각 1·5·9·13·17·21시) 코인 60개 각각의 "4시간 뒤에 올라 있을 확률"과 "8시간 뒤에 올라 있을 확률"을 기록합니다.
- 모델이 특히 확신하는 예측에는 "확신 상위 10%" 표시가 붙습니다. 8시간 예측에는 "상위 5%"도 따로 집계합니다.
- 연구에서 처음 보는 코인에 적용했을 때 확신 상위 10%의 적중률은 4시간 55.9%, 8시간 57.5%였고, 8시간 상위 5%는 58.7%였습니다(`docs/research/direction_result_v7.md`). 다만 최근 9개월은 그보다 낮았습니다.
- "시장 대비" 예측도 함께 기록합니다. 그 코인이 60개 코인의 중간보다 더 오를지를 맞히는 것입니다. 연구에서 처음 보는 코인 46개의 확신 상위 10%가 4시간 56.7%, 8시간 58.1%였고, 다섯 해 모두 55%를 넘었습니다(`docs/research/direction_result_v11.md`). 2026-11-12에 코인 간 순위 특징을 넣은 모델로 바꿨고, 화면은 그 뒤의 예측만 채점합니다. 시장 전체가 내리면 맞혀도 가격은 내릴 수 있습니다.
- 화면의 "코인 조회"에서 코인을 고르면, 마지막 4시간봉 마감 기준으로 그 코인의 4시간·8시간 뒤 오를 확률과 확신 순위(60개 중 몇 위, 상위 10%·5% 여부)가 나옵니다. 고른 코인은 다음에 열 때도 유지됩니다.
- "지금 시세로 예측" 버튼을 누르면 그 순간의 시세로 60개 코인을 다시 계산해 같은 값을 보여 줍니다. 1~2분 걸리고, 예측 기록기가 켜져 있어야 합니다.
  - 4시간봉 마감이 아닌 시점의 예측은 연구에서 검증한 적이 없습니다. 적중률을 알 수 없고 채점 기록에 넣지 않습니다.
  - 나중에 확인할 수 있게 `runtime/predictor/now_predictions.jsonl`에 따로 저장합니다.
- 예측 기간이 끝나면 실제 결과로 채점합니다. 4시간 예측, 8시간 예측, 시장 대비 예측은 따로 채점합니다.
- 모델은 예측하는 60개 코인 전체로 학습합니다. 매달 1일에 그때까지의 데이터로 다시 학습합니다.
- 적중률은 확인됐지만, 실제로 수익이 나는지는 확인되지 않았습니다. 이 기록의 목적은 앞으로의 성적을 정직하게 쌓아 보는 것입니다.
- 나중의 연구를 위해 미결제약정, 롱숏 비율, 호가 쏠림, 강제청산도 함께 모읍니다. 거래소가 과거 기록을 주지 않는 데이터라 켜 둔 동안만 쌓입니다.
- 주문을 내지 않고 API 키를 읽지 않습니다. 바이낸스 공개 시세만 씁니다.
- 마감 후 15분 안에 예측하지 못한 봉은 건너뜁니다. 맥북이 잠들었다 깨어나서 뒤늦게 예측하는 일은 없습니다.
- 기록은 `runtime/predictor/`에 남습니다. 끌 때는 `./run_predictor.sh stop`을 실행합니다. 재부팅하면 다시 켜야 합니다.
