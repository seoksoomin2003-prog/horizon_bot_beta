# 맥북 실행 안내

서버나 systemd 없이 맥북에서 실행합니다. 기본은 **가상 매매**입니다. 실제 주문이 나가지 않고, API 키도 읽지 않으며, 거래소 공개 시세만 씁니다.

## 설치 (처음 한 번)

```bash
cd ~/Projects/horizon_bot_beta && ./run_mac.sh setup
```

## 가상 매매

시작:

```bash
./run_mac.sh start
```

현황:

```bash
./run_mac.sh status
```

최근 로그:

```bash
./run_mac.sh logs
```

중지:

```bash
./run_mac.sh stop
```

- 비정상 종료 시 자동으로 다시 시작합니다. 맥북을 재부팅하면 `start`를 다시 실행해야 합니다.
- 전원을 연결해 두세요. 덮개를 닫으면 잠자기로 기록이 끊길 수 있습니다. 다시 켜지면 놓친 1분봉으로 손절·익절을 다시 계산합니다.
- 시작 자금은 50 USDT입니다(실제 자산 규모에 맞춤, 2026-11-08). 바꾸려면 시작 전에 `.env`에 `PAPER_INITIAL_EQUITY=값`을 넣으세요.
- 기록은 `runtime/paper_binance/`, `logs/paper/`에 저장되고 실거래 폴더와 섞이지 않습니다. 초기화하려면 봇을 중지한 뒤 이 두 폴더를 지우면 됩니다.

## 가상 매매 결과의 한계

체결은 가정으로 계산합니다: 수수료 0.05%, 슬리피지 0.05%, 손절은 표시가격이 아닌 1분봉 체결가 기준입니다. 자금조달비용, 강제청산, 호가 깊이, 부분 체결은 반영하지 않으므로 실제 결과는 더 나쁠 수 있습니다. 거래가 적으면 수익성을 판단할 수 없습니다.

## 실거래 전 점검

실거래는 직접 판단해서 켜야 합니다. 원금 이상의 손실이 날 수 있는 선물 거래입니다. 켜기 전에 아래를 모두 확인하세요.

1. 가상 매매로 2~4주 이상 돌려 오류와 거래 내용을 확인했습니다.
2. API 키의 출금 권한이 꺼져 있습니다. 키가 서버 IP로 제한되어 있으면 새로 설정했습니다.
3. `.env`를 iCloud 동기화 밖에 두었습니다. Desktop이 iCloud 대상이면 폴더를 `~/Projects`로 옮기세요.
4. 거래소에서 실제 포지션과 미체결 주문을 직접 확인했습니다.
5. `runtime/binance/`에 예전 테스트가 남긴 값이 있습니다. 4번을 확인한 뒤 이 폴더를 백업하고 비웠습니다. 특히 `degradation_state.json`의 `CRITICAL_PROTECTION_FAILURE`가 남아 있으면 신규 진입이 막힙니다.
6. 거래소 계정의 레버리지와 마진 모드를 확인했습니다. 봇이 직접 설정하지 않습니다.
7. 맥북이 꺼지면 거래소의 손절 주문만 남습니다. 익절 분할, 손절가 이동, 재시도는 멈춥니다.

실거래 시작 (`.env`에 키가 있어야 하고, `DEMO_MODE`는 꺼야 하며, 확인 문구를 직접 입력해야 합니다):

```bash
./run_mac.sh start --live
```

## 보기 전용 화면

```bash
./run_dashboard.sh
```

브라우저에서 `http://127.0.0.1:8791`이 열립니다. 잔고, 포지션, 손익, 체결, 오류를 10초마다 새로 보여 줍니다. 끌 때는 `./run_dashboard.sh stop`을 실행합니다.

- 봇과 별개 프로그램이라 켜고 꺼도 봇에는 영향이 없습니다.
- 이 맥북에서만 열리고, 주문이나 설정을 바꾸는 기능이 없습니다.
- `.env`를 읽지 않고 인터넷에 연결하지 않습니다. 그래서 미실현 손익은 보여 주지 않습니다.
- 맥북을 재부팅하면 다시 실행해야 합니다.
